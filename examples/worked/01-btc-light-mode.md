# Worked example — LIGHT mode

**User:** Quick read on BTC?

This is a single-asset question with no decision attached, so the skill runs in
LIGHT mode: one primary scenario, its confidence, and the one thing that would
prove it wrong. It does **not** invent a current price — it reasons from what the
user supplies or asks the user for the missing input.

---

**Output (shape):**

> **BTC — LIGHT read**
>
> **Structure:** price holding above the prior accumulation range; higher-low
> sequence intact on the higher timeframe. *(observed — from your chart/input)*
>
> **Primary scenario (confidence ~60%):** continuation higher while the range low
> holds. The move is structural, not narrative — it rests on the higher-low
> sequence, not on sentiment.
>
> **Invalidation:** a decisive close back **inside** the prior range. That breaks
> the higher-low sequence and the read is void.
>
> **What would sharpen this:** current price relative to the range low, and
> volume on the last leg up.

---

**Why it is shaped this way**

- One scenario, because LIGHT mode is for a quick read, not a full deliberation.
- A confidence number, because a read without one hides how much to trust it.
- An invalidation, because the FAILURE SYSTEM rejects any output without one.
- A "what would sharpen this" line, because naming the missing input is honest;
  inventing the input is not.
